# Binance Agentic Wallet — existing NFT mining

The project CLI uses Binance's official `baw` external-contract preview/execute flow on BNB mainnet. It checks the NFT and vault protocol IDs, the vault's NFT/reward-token links, wallet ownership, referral binding and individual NFT approvals. Destinations are taken from the published production manifest. No contract upgrade, web-page change, server-side wallet session, or owner/verifier private key is involved.

Entry point: `scripts/agentic-wallet.mjs`; agent instructions: `skills/onhold-agentic-wallet/SKILL.md`. Supported commands are status, positions, preview, execute and receipt. Supported mining intents are stake, claim and unstake. A stake intent yields one prerequisite at a time. Every execute requires its saved preview, explicit confirmation, a matching wallet, a fresh state check and an unexpired Binance request. A persisted unresolved-send marker plus a local execute lock prevents silent resubmission after response loss. Receipts verify transaction sender, destination, calldata, zero native value, a block after the preview, three confirmations and the expected contract event.

Local validation uses Anvil chain 56 and the actual OnHold NFT and production gameplay implementation behind ERC1967Proxy. Only the Binance service adapter is simulated. Tests transfer an eligible NFT into the simulated Agentic address, bind its inviter, approve only that NFT, stake it, advance time, receive reward tokens and unstake it back. Additional checks cover wrong chains/deployments/owners, zero-weight NFTs, invalid IDs, missing inviter choice, disabled Developer Mode, missing confirmation, concurrent lock ownership, changed previews, replay, App-pending responses, and a response lost after an actual local-chain broadcast. This is not a real Binance wallet test.

The official CLI 1.11.0 is installed in the ignored project tool directory. Initial official checks reported skill 1.13.0 current, CLI version sufficient and wallet UNCONNECTED. Real wallet connection, Developer Mode and the mainnet NFT position must be checked before any real transaction. No mainnet transaction has been sent by this integration yet.

Real authentication is blocked by the local network. The official `auth signin` command returned `NETWORK_ERROR: Client network socket disconnected before secure TLS connection was established`. One retry through the user's existing local HTTP proxy returned `NETWORK_ERROR: Proxy response (503) !== 200 when HTTP Tunneling`. No pairing code or login URL was issued. The system proxy and wallet security settings were not changed. The user needs to restore network access before the real Binance flow can continue. The user explicitly selected completing the real wallet flow first and adding a website entry later.

Scope remains the three existing-NFT actions. AI mint authorization (the website currently uses personal-message signatures), website AI-wallet controls, automated NFT transfer and exclusive AI-wallet gating are deferred.
